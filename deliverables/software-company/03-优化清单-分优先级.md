- **验收**：`git status` 干净；`mvn clean package -DskipTests` BUILD SUCCESS。

### OPT-01【正确性头号】缓存新鲜度校验
- **位置**：`AnalysisCacheService.java:399`（`projectFingerprint()` 实现完整但**零调用**）、`:156`（指纹只算入口 key）、`:343-350`；`AnalysisService.java:266-286`
- **现状**：改代码 → 重编译 → 重新分析 → **仍返回旧结果，且不报错**。缓存文件名刻意不含指纹。
- **动作**：`save` 时把指纹写进缓存文件（或独立 `.fingerprint` 文件），`load` 时比对，不匹配即判定 `dirty=true` 触发重算。指纹须覆盖：class 文件的 mtime+size 集合、pom 哈希、分析参数（maxDepth / 过滤规则版本）。
- **验收**：改一个被分析方法体 → 重新编译 → 重新分析 → 结果**必须**变化；未改动时缓存仍命中（热路径 0.26s 不被破坏）。

### OPT-02【安全·已实测可利用】缓存文件名越界校验
- **位置**：`AnalysisCacheService.java:255-258`（`loadByFileName`）
- **现状**：QA 已实测 `GET /api/projects/{id}/cache/load?fileName=C:\Users\...\xxx.json` → **HTTP 200 / 3.5 MB**。跨盘符绝对路径下 `Path.resolve` 直接返回绝对值，等于任意文件读。
- **动作**：`String` → `Path.of(name).normalize()`，拒绝绝对路径与含 `..` 的值，且校验 `startsWith(cacheDir)`；非法直接 400。
- **验收**：上述请求返回 400；正常文件名仍可读；加一条单测覆盖 `../`、`C:\`、空值三种输入。

### OPT-03【安全·本项目最实质高危】"克隆即编译"加确认与来源白名单
- **位置**：`GitPrepareService.java:158`（克隆后立即 `mvn compile`）、`MavenCompileService.java:132,141-145`、`AnalysisController.java:187-190`
- **现状**：Maven 生命周期会执行 pom.xml 绑定的任意插件代码 → 克隆不可信仓库即 RCE。**不是理论风险**：实测 `/api/projects` 注册表里已有 github.com 上的 kkFileView、spark-live-classroom 两个真实外部项目。
- **动作**（分两步）：
  1. 短期（1h）：`application.yml` 增加 `callgraph.git.allowed-hosts` 白名单，非白名单 host 的仓库**只克隆不编译**，并在 UI 明确提示"该来源不在白名单，未自动编译"；
  2. 根治（后续立项）：把编译放进容器 / 独立低权限用户。
- **验收**：导入白名单外仓库 → 不触发 `mvn compile` 且有明确提示；白名单内行为不变。

### OPT-04【安全】`javac` 加 `-proc:none`
- **位置**：`JavacCompileService.java:87-102`
- **现状**：classpath 由被分析仓库内收集的 `*.jar` 拼成，未加 `-proc:none`。javac 会按 `META-INF/services/javax.annotation.processing.Processor` 自动发现并**在本工具自己的 JVM 内执行**注解处理器 → 投毒 jar 即 RCE。
- **动作**：args 追加 `-proc:none`。
- **验收**：无构建工具的纯 Java 工程仍能正常编译出 class。

### OPT-05【测试】测试桩补重载
- **位置**：`GitPrepareServiceTest.java:28`（`StubCompileService`）
- **现状**：生产调的是 `compile(Path, Consumer<String>)`（`GitPrepareService.java:158`），桩只覆写了 `compile(Path)` → 桩被绕过 → 真跑 mvn → 夹具 pom 是非法 `<project/>` → `modelVersion is missing`。
- **动作**：
  ```java
  @Override
  public CompileResult compile(Path projectDir, java.util.function.Consumer<String> onLine) {
      return compile(projectDir);
  }
  ```
- **验收**：`test_prepare_cloneCompileDone` / `..._compileFailure_marksFailed` / `..._backendInSubdir_located` 三个用例转绿。

### OPT-06【测试】路径校验改 400
- **位置（已据 QA 复核修正）**：真实 500 源头是 `AnalysisController.java:178` 的 `compileIfNeeded()` —— 对不存在路径 `Files.walk` 抛 `NoSuchFileException` 被通用 catch 包成 500；`EntryScanService.java:113` 的 `scanWithProfile` 也会抛 500。`AnalysisControllerTest.java:197`（`test_scanEntries_badPath_rejected`）断言 400 却拿到 500。
- **已落 commit**：`066b751` + `9fc572c`（在 `compileIfNeeded` 开头加 400 守卫）+ `72e1cc9`。
- **验收**：`test_scanEntries_badPath_rejected` 转绿。`compileIfNeeded` 的 400 守卫不误伤合法路径（合法但无编译产物的路径会继续走编译流程）。

### OPT-07【前端正确性】`escapeHtml` 去重
- **位置**：`app.js:3541` 与 `app.js:3925`（同一作用域两份同名定义）
- **现状**：后者覆盖前者，且**不转义单引号**。
- **动作**：保留一份（补 `'` → `&#39;`），删除另一份。
- **验收**：全文 `escapeHtml` 只出现 1 处定义；方法签名含单引号时能正常显示。
