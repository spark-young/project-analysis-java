# 批量分析：全量加载调用链 + 项目级方法搜索

## Context（背景与目标）

用户使用该工具时**通常对整个项目做分析**。当前批量分析完成后，界面只展示每入口的摘要行（`kind==='batch'` 轻量索引），**具体调用链与"方法调用次数分析"要点击某入口的"查看调用链"才单独加载**——这与"对全项目分析"的需求不符。

- 根本原因在 `BatchAnalyzeService#startAsync` 的既有设计（"不合并全部调用链，避免膨胀到 GB 级"）。
- 好消息：图结构迁移（`schema=2`）把单入口结果从 64MB 降到约 1-2MB，**"全部加载"如今可行**（46 入口约几十 MB，浏览器端内存可接受）。
- 用户确认：**批量分析完成后自动并行加载全部入口调用链**，全部就绪进入"加载完成态"，随后支持在**项目维度搜索某方法被哪些交易入口调用** + **项目级方法调用次数分析**。进度条对用户呈现为**一条整体"加载进度"**（分析阶段 0–80%，无缝续接"加载全部调用链"阶段 80–100%，不区分两段）。

## 方案（前端实现，不改后端数据结构）

所有数据已存在：每个入口都单独落盘了一份完整缓存（`/api/projects/{id}/cache/load-file?file=<fileName>` 返回 `graph + methodFrequency + stats`）。方案是在 `renderBatchSummary` 触发**并发拉取全部入口缓存进内存**，建立项目级索引与频率，树的 DOM 仍按入口按需渲染（避免一次性物化海量节点）。

### 1. 批量全量加载（并发 + 统一进度）
- 模块级新增 `batchModel`：`{ projectId, entries:[{entry,result,status,err}], done,total,failed, index:Map, projectFreq:[], key }`。
- 在 `renderBatchSummary`（app.js ~774）开头重置 `batchModel`（按 `projectId+批次` 判断变化，防止跨项目串数据），随后**自动触发全量加载**。
- 并发 worker 池 `loadAllBatchEntries(batch,{limit:8})`：队列 + 最多 8 个 in-flight，逐个调 `/cache/load-file`（抽出 `fetchEntryFile(fileName)`）。
- **统一进度**：复用 `els.batchProgressBar/Text`。分析阶段轮询已到 `st.progress`（0~~80）；进入加载链阶段从 ~80 续增到 100（`80 + 20*done/total`），全程对用户只显示一条"加载进度"。
- **命中缓存不再重复 fetch**：已按 `fileName` 存在 `batchModel` 的完成项直接复用。
- **加载完成态**：全部（或可加载部分）就绪后显式切换为"已加载 n/46（失败 m 可重试）"，随后启用项目搜索面板。

### 2. 项目级方法索引（核心：某方法被哪些交易入口调用）
- **直接遍历每入口 `graph.methods`**（它本身就是从根可达的方法闭集；构建期只物化可达方法，环只置位不强加边，故无死循环）。✓ 已验证，无需对 edges 做 BFS/DFS。
- 主键 `batchMethodKey(m) = m.owner + '#' + m.name + m.descriptor`（含返回类型，唯一）；展示用 `m.display`。注意：**不能**用 `methodFrequency.method`（identifier 不含返回类型会碰撞）。
- `buildProjectIndex(results)` → `Map[key] → { source, entries:Set<entryIdx> }`，`entryIdx` 回指 `batch.entries[idx]`（其 `fileName` 用于跳转）。

### 3. 项目级方法调用次数分析
- `buildProjectFreq(results)`：对每入口 `graph.edges`，以 `to` 侧按 `batchMethodKey` 累加 `callCount`，caller 用 `graph.methods[from].display`，行号取 `edge.line`，产出 `{method:identifier, source, callCount, callers}` 数组。
- 喂现有 `updateFreqFilterChips` + `renderFreqList`（app.js ~983/998），**来源过滤与样板规则自动生效**；切换项目模式时重置 `freqFilter='ALL'`。
- 口径与后端 `AnalysisService#collectGraphStats` 一致（入度、排除根方法）。

### 4. 项目搜索面板（新建，复用既有渲染习惯）
- **不复用 `runGlobalSearch`**（`matchNode/collectMatches/focusMatches` 绑定在单入口树 DOM 上，数据模型不同）。
- `index.html` 新增面板：搜索输入 + 模糊/精确 + 结果区。
- `runProjectSearch()`：对项目索引按 `method.display/name/owner` 匹配，结果展示"方法名 + 被 N 个交易入口调用"，每个入口一个 chip → 点击打开该入口单树视图（优先用 `batchModel` 内存结果，跳过二次 fetch）。
- 批量视图里现有 `els.globalSearch` 仍隐藏。

### 5. 入口单树视图（保留现状）
- 批量行点击仍进 `renderSingleEntryResult`（由 `loadBatchEntry` 复用 `batchModel` 缓存，命中直接渲染，不重新 fetch）。

### 边界处理
- 入口为 0 或 `graph.methods` 为空：跳过，不建索引/频率。
- `batch.entries` 中 `failed` 无 `fileName`：跳过抓取，失败数并入统计与提示。
- 入口 `stats.truncated`：索引/频率基于物化节点（是"前缀"），完成态提示"基于截断结果，索引可能不完整"。
- `load-file` 部分失败：聚合后提供重试（仅重试失败 `fileName`），不阻塞已成功项。
- 项目切换/重新分析：`batchModel` 必须按 `projectId+批次` 重置。

- `src/main/resources/static/app.js` —— 主要改动：`renderBatchSummary`、`loadBatchEntry`、新增 `fetchEntryFile/loadAllBatchEntries/resetBatchModel/batchMethodKey/buildProjectIndex/buildProjectFreq/runProjectSearch/renderProjectSearchResults/showProjectFreq` 与模块级 `batchModel`。
- `src/main/resources/static/index.html` —— 新增项目搜索面板、（如需）项目频率入口。
- `src/main/resources/static/style.css` —— 项目搜索面板样式。
- 后端无数据结构改动（复用 `/cache/load-file` 与既有批量接口）。

## 验证
1. 启动应用，进入某项目（如 spark-live-classroom，46 入口）做批量分析。
2. 确认：分析完成后**自动**触发"全部加载"，进度条连续 0→100%，最终进入"加载完成 n/46"态。
3. 项目搜索：输入某方法名，看是否列出"被 N 个交易入口调用"，点某入口 chip 能打开该入口调用链树（且不重复请求）。
4. 项目频率区：显示聚合后的全项目高频方法，来源过滤/样板规则/展开调用方均正常。
5. 截断/部分失败入口、重新进入项目读缓存（`load-single`）时，均自动触发全量加载且不串项目。
