# 项目交接 Handover

把"当前项目处于某个阶段要交给另一个团队/另一个 Agent 继续实施"这件事，从口头记忆变成一份**可读、可核验、可续跑**的交接文档。交接的本质是**状态转移，不是聊天总结**——把真实状态写进仓库，接手方能从文件重建上下文，而不是依赖一段可能失真的对话摘要。

## 触发场景

- 项目/某个阶段完成，要**换团队**（人或 Agent）继续实施。
- 用户说"整理交接文档""交给别的团队""写 handover""记录当前进度给接手人"。
- 一个长会话要结束，需要把上下文固化到文件后再续接。

## 三种使用方式

1. **generate**（默认）——生成/更新一份自包含交接文档。
2. **resume**——接收方在新会话读取交接文档，先**核验**文档与当前代码/测试真实状态是否一致，再继续工作（不要盲信文档）。
3. **cleanup**（可选）——确认工作全部闭环后清理临时交接产物。

只写当前已确知的状态，**不要顺手开始做下一个阶段的工作**——那是接手方的活。

## 生成步骤

对当前项目做一次"蒸馏"（distill），把已知信息整理成结构化文档，写入 `docs/xx-项目交接文档.md`（如已存在则增量更新，不覆盖历史交接要点时追加 timestamp 快照）。

### 1. 先探真相，再写文档（不猜）

用工具核实，而不是凭记忆：
- `git log --oneline -n 20`、`git status`：当前分支、最近改动、是否有未提交内容。
- 读 `pom.xml` / `AGENTS.md` / `CLAUDE.md` / `application.yml` 等项目说明与配置，确认技术栈、入口、运行方式。
- 跑一遍测试命令（如 `mvn -B test`），记录**实际验证过**的结论。
- 渲染过、跑起来过才算"已验证"；只是假设的，放进 `<未知项>`，不要写进 `<当前状态>`。

### 2. 按固定结构组织文档

交接文档应包含以下小节（标题可用中文，结构固定以便解析）：

- **一句话定位** —— 项目是什么、给谁用、解决什么问题。
- **目标与方向** —— 本阶段目标为什么做；下一阶段方向/迭代项（未承诺、未开启）。
- **当前进度总览** —— 用表格：每模块/能力 完成 / 进行中 / 未开始 / 已知问题。
- **技术栈与选型** —— 组件+版本+为什么选它；**锁定版本/硬性约束**必须单独强调。
- **总体架构与设计思路** —— 数据流图（自顶向下）+ 核心设计要点。
- **关键实现文件地图** —— 层 / 文件 / 职责，含 API 一览。
- **测试与验证状态** —— 单元测试数/通过率、E2E 实测记录、测试入口。
- **部署与使用说明** —— 环境要求、构建、启动、常见坑。
- **约束与教训（勿动 / 必守）** —— 硬性约束、工程规范、踩过的坑。
- **后续实施 / 下一步** —— 按优先级列出的精确下一步动作。
- **X-验证/假设分离块**：
  - `<已验证>` —— 实际跑过/测过/渲染过的结论。
  - `<未知项/勿假设>` —— 明确未验证、接手前必须核实的东西。
  - `<真相优先级>` —— 交接文档与现状冲突时以哪个为准。

**真相优先级（从高到低）**：`运行中的代码 > 测试 > 文档 > PROGRESS > 本交接文档 > 更早的交接` —— 过期的文档永远不能压过活代码。

### 3. 隐私与安全边界（强制）

- 交接文档**禁止**写入：凭证/Token/密钥、内网地址不必要细节、cookie、真实用户数据。
- 敏感连接方式只写"占位说明"，如"Token 每次填写，见部署接线人"。
- 若项目文档已有安全约定（如只绑 127.0.0.1、零出站网络），在"约束"里保留。

### 4. 收尾

- 保存后在回复里给出：文档路径 + 一行"续跑指令/要点"，便于接收方或新会话快速接上。
- 提示是否同步到项目记忆（training-log → index.html → README → project_memory）。

## Resume（接收方流程）

1. 读取交接文档与对应技术方案。
2. **核对**：`git status`、当前分支/HEAD、关键文件与测试是否与文档一致；发现不一致 → 以真实代码为准，并记录漂移。
3. 复述阶段目标与下一步，确认后再动手改任何东西。

## 示例

示例：Java 字节码方法调用链工具，阶段完成要交给另一团队。
- generate 产物：`docs/00-项目交接文档.md` + 配套技术方案，含 REST/Dubbo/ElasticJob 入口分析、JGit+Maven 集成、80/80 测试全绿、JGit 版本锁定等硬性约束。
- resume：接收团队在新会话读该文档→核验 `mvn -B test`→确认下一步入口扩展范围后再动手。
