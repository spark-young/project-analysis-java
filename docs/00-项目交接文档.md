## 1. 项目定位一句话

给**内网**用的 **Java 静态方法调用链分析 Web 工具**：喂给一个已编译的 Java 工程（本地路径 **或** Git 仓库自动拉取编译），自动发现**交易入口**（REST 接口 / Dubbo 服务 / ElasticJob 作业 / main 启动类），按入口"自顶向下"把调用链以**可展开/收缩的树**展示到网页，并导出 **Excel 报告**（含项目方法与依赖引入方法）。

## 3. 项目背景与业务目标

### 3.1 为什么做
公司内网要求对某个 Java 项目的代码做**调用链说明**，但存在安全红线：**不能引入成品 exe/二进制工具，不能有出站网络、不能被分析项目执行**。因此选择走**纯源码 + 字节码静态解析**路线，交付形态为**源码工程（可送审） + fat jar**。

### 3.2 要解决的核心问题
1. **分析目标**：给定"类"或"类+方法"，打出它向下调用的全部方法链——既包括项目自身方法，也包括**依赖 jar 引入的方法**（递归展开到 JDK 边界）。
2. **入口模式**：用户实际关心的是**交易链路**，所以要从交易入口（REST/Dubbo/ElasticJob/main）出发向下分析，而不是手填类名。
3. **两种输入**：本地已编译项目路径；或 Git 仓库地址（自动 clone → mvn compile → 再分析）。
4. **两种输出**：网页树形展示（可展开收缩，可搜索）+ Excel 报告。

### 3.3 竞品/可选方案为何不采用
- 成品 exe（如现成二进制工具）：违反内网安全合规，不放行。
- 源码级全量解析/IDE 索引库类方案：重、慢、部署复杂；ASM 字节码解析轻量可控。
- GitHub 现有同类：需自研满足"交易入口 + 依赖方法全列 + 内网依赖可私有仓库安装"的组合需求。

## 5. 总体架构与设计思路

### 5.1 数据流（自顶向下）
```
输入源
 ├─ 本地路径 ─────────────────────────┐
 └─ Git 仓库(地址/分支/Token)          │
     └→ GitPrepareService(异步)       │
         ├ 克隆(JGit) → mvn compile   │
         └→ 产出可分析的项目目录 ───────┘
                  ↓
        ClasspathResolver(布局识别)   ← 多模块递归收集 target/classes + 依赖 jar 并集
                  ↓
    ClassMetadataRegistry(注册表)     ← Phase A: SKIP_CODE 索引类头/方法表/注解
                  ↓
      EntryPointDetector(SPI) 扫描交易入口
     REST / DUBBO / ELASTIC_JOB / MAIN
                  ↓
    AnalysisService.analyze(entries 或 className)
       CallGraphBuilder → 多棵树(DFS,环检测,深度/节点上限)
                  ↓
     JSON 树 → 前端渲染           +   ExcelReportGenerator → xlsx
```

### 5.2 核心设计要点
1. **两阶段解析**：Phase A 用 `ClassReader.SKIP_CODE` 快速索引全部 class（类层次 + 方法表 + 注解，快）；Phase B 仅对树中被展开的类做全量 Code 解析提取调用指令。
2. **调用点解析语义**：虚调用按**静态接收类型**解析；接口/抽象方法 → 枚举注册表全部具体实现（含 default 兜底）；JDK 包排除；类未知 → EXTERNAL 叶子。只做向下调用链。
3. **入口探测器=SPI**：`EntryPointDetector`(type/label/detect)，新增入口类型只需实现接口 + `@Component`，无需改主流程（为将来扩展公司内部框架入口预留）。
4. **注解索引**：ClassMetadataRegistry 记录类/方法级注解及属性值（ASM 解析），供探测器读取（如 REST 的 value/path/method）。
5. **Git 任务模型**：单线程执行器（避免并发拉取抢资源）；状态机 `PENDING→CLONING→COMPILING→DONE/FAILED`；**DONE 保留临时目录**供后续扫描/分析/Excel 复用，**FAILED 立即清理**；前端 2s 轮询。
6. **安全设计**：默认只绑定 `127.0.0.1:8080`；对被分析项目**只读不执行**（ASM 加载 class 但执行不了业务代码）；零出站网络。
7. **Excel 6 列**：`层级 | 方法标识 | 来源 | 调用方式 | 行号 | 备注`，方法标识 = `全限定类名#方法名(参数类型)`，纯数据无缩进，可筛选/VLOOKUP。

## 6. 关键实现文件地图

| 层 | 文件（src/main/java/com/spark/callgraph/...） | 职责 |
|---|---|---|
| 启动 | `CallGraphApplication.java` | Spring Boot 启动，默认 127.0.0.1 |
| 引擎/模型 | `engine/model/*` | MethodKey/ClassInfo/CallNode/InvokeType/SourceType/Resolution/AnnotationInfo/RawCall |
| 索引 | `engine/ClassMetadataRegistry.java` | 类层次+方法表+注解索引注册表、调用点解析、subtype/imple 查询 |
| 字节码 | `engine/MethodCallExtractor.java` | ASM 提取方法体调用指令（含 Lambda/方法引用） |
| 布局/依赖 | `engine/ClasspathResolver.java`、`PomDependencyResolver.java`、`MavenRepoLocator.java` | 布局识别（Maven 单/多模块/Gradle/fatjar/lib）、POM→.m2 jar、仓库定位 |
| 构树 | `engine/CallGraphBuilder.java` | DFS 构树（环检测/深度/节点上限/同级去重） |
| 入口探测器 | `engine/entry/{EntryPointDetector, EntryPoint, RestControllerDetector, DubboServiceDetector, ElasticJobDetector, MainMethodDetector}.java` | 交易入口 SPI + 四探测器 |
| 编排 | `service/AnalysisService.java` | 布局→注册表→入口解析→树；**支持 entries 多入口分析与缓存复用** |
| 入口扫描 | `service/EntryScanService.java` | 跑全部探测器→按类型分组 |
| Git | `service/{GitCloneService, MavenCompileService, GitPrepareService}.java` | 克隆、调 mvn 编译、异步准备任务 |
| 异常 | `service/AnalysisException.java` | 带 HTTP 状态码的业务异常 |
| 报告 | `report/ExcelReportGenerator.java` | Excel（总览 + 每入口方法一 Sheet） |
| Web | `web/AnalysisController.java`、`GlobalExceptionHandler.java` | REST API + 错误映射 |
| DTO | `service/dto/*` | AnalyzeRequest/EntryRef/EntryScanResult/GitPrepareRequest/GitPrepareStatus/ScanRequest/ProjectInfo/AnalysisResult |
| 前端 | `resources/static/{index.html, app.js, style.css}` | 页面 |
| 配置 | `resources/application.yml` | 端口/绑定地址/JSON |

**API 一览**（详见技术方案 §5）：
- `GET /api/project/info?path=`
- `GET /api/classes/search?path=&q=`
- `GET /api/defaults`
- `POST /api/scan/entries` → 交易入口分组清单
- `POST /api/git/prepare` + `GET /api/git/prepare/{jobId}` → Git 异步准备/轮询
- `POST /api/analyze` → 全树 JSON（`className` 或 `entries[]` 二选一）
- `POST /api/report/excel` → xlsx

## 8. 部署与使用说明（移交须知）

### 8.1 环境要求
- JRE **8**（最低）~ 21（已实测 21）
- 服务器需装 **Maven**（`mvn` 在 PATH），用于 Git 场景下对拉取工程编译；本地场景若工程已编译则不需要 mvn。
- 内网依赖：fat jar 已含全部运行时依赖；若走源码编译需私服有 `docs/...md §14` 的依赖构件。

### 8.2 构建
```bash
mvn -B test          # 80/80 全绿
mvn -B package -DskipTests   # 出 jar（若 8080 被占/服务在跑会因文件锁导致 repackage 失败，先停服务）
```

### 8.3 启动
```bash
java -jar target/call-graph-analyzer.jar
# 浏览器 → http://127.0.0.1:8080
```
- 页面加载自动预填演示项目（工具自身），可直接"开始分析"体验。
- **Git 场景**：切"Git 仓库"tab，填仓库地址（+/分支/Token/用户名）→"拉取并编译"→轮询状态→DONE 自动扫描交易入口→勾选入口"分析勾选入口"。
- 自定义本地 Maven 仓库：系统属性 `callgraph.maven.repo` 或环境变量 `CALLGRAPH_M2_REPO`。

## 9. 项目记忆 / 关键约束与教训（务必遵守）

### 9.1 硬性约束
1. **JGit 版本固定 `5.1.3.201810200350-r`**，不可升级。
2. 部署服务器 **必须有 Maven**（快速联调时建议本机也装）。
3. **Token 每次填写**（当期设计不持久化 Token）。
4. 第一期 Git 分析**只支持 Maven 项目**（含多模块）；Gradle 的 Git 编译不在本期范围。
5. 入口分析**必须从交易入口自顶向下**，探测器 SPI 机制不许绕过。

### 9.2 工程规范 / 教训
- 入口探测器走 SPI + `@Component` 注册，扩展新入口类型不动主流程。
- 多模块：递归收集每个 module 的 `target/classes` 并合并依赖并集。
- Git 项目名要显示**仓库名**（`repoDisplayName()` 取 URL 末段去 `.git`），不要显示临时目录名。
- **JDK 兼容教训**：pom/生成项目若未显式声明 `maven.compiler.source/target`，默认 source 5 会在 JDK≥17 报"不再支持源选项 5"——务必显式声明为 8。测试夹具 pom 已处理。
- Windows 下运行中的 jar 会被锁文件导致 `repackage` 失败 → 先停服务再打包。
- 被分析产物类若含 BOM/编码异常会导致编译失败，确保 UTF-8 无 BOM。

## 10. 后续方向 / 建议迭代项

> 以下为**已知可增强**的点，供接续团队规划（未承诺、未开启）。

1. **更丰富的交易入口类型**：
   - Dubbo **XML** 配置的 `<dubbo:provider>` 解析（当前仅注解式，原文线明确留二期）。
   - 消息消费入口（MQ 消费者）、定时任务（xxl-job/@Scheduled）、事件监听（Spring Event）。
   - 基于 `EntryPointDetector` SPI 扩展公司内部框架入口。
2. **跨方法/跨 service 的调用链增强**（如需）：目前只做"向下"；可评估"向上回溯"（谁调了我）——工作量大需单独立项。
3. **前端**：大项目树很深的懒加载性能、调用链差异对比、`entries` 批量勾选后的调用链**合并去重视图**、报表按模块/包维度统计。
4. **安全与分发**：Token 由服务端密文保管（Vault / 配置中心）而非页面明文；支持绑定局域网 IP + 访问控制。
5. **可观测性**：处理"结果截断"（链过长/节点超上限）时的用户提示与分阶段展开。
