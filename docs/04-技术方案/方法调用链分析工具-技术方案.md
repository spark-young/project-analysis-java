# Java 方法调用链分析工具 - 技术方案

状态：已实现（v1.1：交易入口分析 + Git 集成）

## 1. 功能概述与目标

内网安全合规的 Java 静态调用链分析工具（全源码白盒，无任何出站网络行为）：

- 输入（两种来源，页面 tab 切换）：
  - 本地：服务器本地路径上的已编译 Java 项目 + 类名（分析整个类）或 类名+方法名（分析具体方法）
  - Git：GitLab / GitHub / 内网 Git 仓库地址 + 可选 Token → 工具自动克隆 → mvn compile → 直接进入交易入口分析
- **交易入口分析**：扫描项目的业务入口——REST 接口（@RestController/@Controller + 映射注解）、Dubbo API（@DubboService/@Service(dubbo)、XML 不支持）、ElasticJob 作业（SimpleJob/DataSourceJob 接口实现）、main 启动类；按类型分组展示、勾选若干入口后一键分析全部调用链
- 输出 1：HTML 树形调用链，节点可展开/收缩
- 输出 1a：每个方法行带 🔎 搜索按钮，支持模糊（包含、忽略大小写）/精确（方法名、`类.方法` 完整匹配）搜索该方法子树，命中自动展开路径 + 黄色高亮 + 滚动定位，未命中给出明确提示
- 输出 1b：结果区全局搜索条——一次搜索所有入口方法的调用链（类分析/入口分析多入口场景），按入口分组显示命中 chips（含命中数），点击 chip 展开该入口路径并高亮全部命中
- 输出 2：Excel 报告，每个入口方法一个 Sheet，列出其调用的全部方法
  - 列：层级 | 方法标识 | 来源 | 调用方式 | 行号 | 备注（6 列纯数据，无缩进，树形结构由层级数字表达）
  - 方法标识为 `全限定类名#方法名(参数类型)`（如 `com.foo.Bar#pay(String)`，构造器 `#<init>`），可直接复制/筛选/VLOOKUP
- 覆盖：项目自身方法 + 依赖引入方法（递归展开到 JDK 边界为止）
- 排除 JDK 方法（java.*/javax.*/jdk.*/sun.*/com.sun.* 等）
- 只做向下调用链（A 调用了谁）
- 多模块 Maven 项目：递归收集全部 module 的 target/classes 并合并依赖

## 4. 数据模型

- `MethodKey`：owner(内部名) + name + descriptor，唯一标识方法
- `ClassInfo`：superName、interfaces、isInterface/isAbstract、方法表(name+desc→access)、来源(PROJECT/DEPENDENCY)
- `CallNode`：MethodKey + source(PROJECT/DEPENDENCY/EXTERNAL) + invokeType(VIRTUAL/STATIC/INTERFACE/SPECIAL/DYNAMIC) + line + cycle + truncated + children
- `Resolution`：调用点解析结果 → SINGLE(具体方法) / MULTI(接口或抽象的全部实现) / JDK(排除) / EXTERNAL(类不在类路径，叶子展示)

## 5. 接口定义

| 接口 | 说明 |
|---|---|
| GET /api/project/info?path= | 校验路径、识别布局、统计类/依赖 jar 数 |
| GET /api/classes/search?path=&q= | 项目类名搜索（自动补全） |
| GET /api/defaults | 页面默认演示值（本工具自身：jar 路径 + AnalysisService.analyze） |
| POST /api/scan/entries | body: {projectPath} → 按类型分组的交易入口清单（REST/DUBBO/ELASTIC_JOB/MAIN，display 如 `GET /api/orders`） |
| POST /api/git/prepare | body: {repoUrl, branch?, token?, username?} → 异步任务 {jobId, status} |
| GET /api/git/prepare/{jobId} | 轮询任务状态：PENDING → CLONING → COMPILING → DONE（含 projectPath 可直接分析）/ FAILED（含排错输出） |
| POST /api/analyze | body: {projectPath, className, methodName?, maxDepth?, entries?} → 全树 JSON；entries（来自入口扫描勾选）与 className 二选一 |
| POST /api/report/excel | 同 body → xlsx 下载 |

analyze 响应：roots[]（多根：类=每个方法一根，方法=所有重载各一根，entries=每勾选入口一根）、stats、unresolvedDependencies、warnings。

Git 集成说明：prepare 为单线程异步任务（避免并发拉取），DONE 后临时目录保留供后续扫描/分析复用，FAILED 即删；Token 认证用户名默认 github.com→`token`、其余（GitLab 等）→`oauth2`，可显式指定；克隆编译项目名取仓库 URL 末段去掉 `.git`。

## 6. 分析算法

1. **Phase A 索引**：classpath 上所有 .class 用 `SKIP_CODE` 解析出类头+方法表（快），构建注册表；区分项目/依赖来源；跳过 JDK 包
2. **Phase B 按需解析方法体**：仅对树中展开到的类做全量 Code 解析，提取 INVOKEVIRTUAL/STATIC/INTERFACE/SPECIAL + INVOKEDYNAMIC（Lambda/方法引用 → implMethod Handle）
3. **调用点解析**：沿 owner 继承链上溯找具体声明；接口/抽象方法 → 枚举注册表中全部具体实现（含 default 方法兜底）；找不到且链顶是 Object/JDK → 排除；类未知 → EXTERNAL 叶子
4. **构树**：DFS，路径内环检测（环节点标记不再展开）、maxDepth（默认 20）、总节点数上限防爆炸；同级去重
5. 语义：虚调用按**静态接收类型**解析（与主流静态分析一致），接口/抽象分派枚举全部实现

## 12. 交易入口分析设计（v1.1）

按"从交易入口自上而下分析"的使用方式设计，入口探测器为 SPI（`EntryPointDetector`：type/label/detect），新增入口类型只需实现接口 + @Component 注册：

| 探测器 | 识别规则 | display 示例 |
|---|---|---|
| RestControllerDetector | 项目类带 @RestController/@Controller，方法带 @GetMapping/@PostMapping/...（或 @RequestMapping），路径 = 类级 + 方法级拼接；排除 synthetic/bridge | `GET /api/orders` |
| DubboServiceDetector | 项目类带 @DubboService 或 apache/alibaba 两版 @Service 注解，public 非 static 方法；XML 配置的 <dubbo:provider> 不支持 | `dubbo: com.foo.OrderFacade#place` |
| ElasticJobDetector | 项目类实现 SimpleJob 接口（v2 com.dangdang.ddframe / v3 shardingsphere 两套命名空间），具体 execute 方法 | `job: com.foo.OrderSyncJob#execute` |
| MainMethodDetector | 项目类含标准 `public static void main(String[])` | `main: com.foo.DemoApplication` |

- 注解/接口信息来自 ClassMetadataRegistry 的注解索引（ASM ClassReader 解析，注解属性 value/path/method 可取值）
- 入口分析请求：analyze body 的 `entries[]`（className+methodName+methodDescriptor，来自扫描结果勾选），与手动 className 二选一；重载用 methodDescriptor 消歧
- 前端：入口卡片按类型分组（REST/Dubbo/ElasticJob/main 顺序），支持全选/全不选/组内反选/关键字过滤，勾选后一键分析 + Excel 复用同一 entries 请求

## 13. Git 集成设计（v1.1）

流程：`POST /api/git/prepare`（前端表单：仓库地址/分支/Token/用户名）→ 后端异步任务 → 前端 2s 轮询 `GET /api/git/prepare/{jobId}` → DONE 后自动扫描交易入口。

- **克隆**：JGit 纯 Java（服务器无需安装 git 命令）；Token 作为密码（UsernamePasswordCredentialsProvider），用户名默认 github.com→`token`、其余→`oauth2`（GitLab PAT 惯例），均可显式指定；支持指定分支
- **编译**：调用服务器本机 `mvn -B -DskipTests compile`（多模块在根目录执行一次即全部编译）；Windows 下自动探测 mvn.cmd/mvn.bat/mvn；15 分钟超时；失败输出截尾 8000 字符透传给前端排错
- **任务模型**：单线程执行器（避免并发拉取）；状态机 PENDING → CLONING → COMPILING → DONE/FAILED；DONE 保留临时目录（供后续扫描/分析/Excel 复用），FAILED 立即清理；编译产物路径即项目路径，走统一的分析管线（布局识别/依赖解析/入口扫描）
- **限制**：需要服务器有 mvn 和依赖可达（内网私服）；mvn 编译走被分析项目自身 pom 的依赖解析，与本工具的仓库定位逻辑一致（支持 callgraph.maven.repo / CALLGRAPH_M2_REPO 覆盖）
