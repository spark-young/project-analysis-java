# 扫描策略配置

## 1. 目标

为"自动扫描加入清单"功能增加可配置的扫描策略，让用户能灵活控制扫描范围和匹配规则，提高扫描结果的准确性。

## 2. 核心概念

### 2.1 扫描方案（ScanProfile）

扫描方案 = **内置探测器开关** + **自定义规则列表**。

- **内置探测器**：4 个已有的 Spring Bean（REST / DUBBO / ELASTIC_JOB / MAIN），每个可独立启停
- **自定义规则**：用户创建的 6 种规则类型，由通用规则引擎执行

### 2.2 预设方案（内置）

| 方案 | REST | DUBBO | ELASTIC_JOB | MAIN | 自定义规则 | 说明 |
|---|---|---|---|---|---|---|
| **标准扫描** | ✓ | ✓ | ✓ | ✓ | 无 | 默认，与现有行为一致 |
| **纯 API 扫描** | ✓ | ✗ | ✗ | ✗ | 无 | 只看 HTTP |
| **定时任务扫描** | ✗ | ✗ | ✓ | ✗ | 无 | 只看 Job |
| **自定义方案** | 可配 | 可配 | 可配 | 可配 | 可配 | 用户从内置复制或新建 |

内置方案不可编辑、不可删除，用户可通过"复制另存"创建自定义方案。

## 3. 规则引擎

### 3.1 6 种规则类型

| # | kind | 含义 | 参数 | 匹配逻辑 |
|---|---|---|---|---|
| 1 | `ANNOTATION_METHOD` | 标注了指定注解的方法 | annotation, excludes | 遍历所有类 → 遍历方法 → 检查方法注解 |
| 2 | `ANNOTATION_CLASS` | 标注了指定注解的类 | annotation, excludes | 遍历所有类 → 检查类注解 → 取所有 public 方法 |
| 3 | `PACKAGE` | 指定包下所有类 | package, recursive, excludes | 遍历所有类 → 匹配包前缀 |
| 4 | `INTERFACE_IMPLEMENT` | 实现/继承了某接口的类 | interfaceName, excludes | 遍历所有类 → 检查 isSubtypeOf |
| 5 | `CLASS_NAME` | 类名通配模式 | pattern, excludes | 遍历所有类 → 类名匹配 glob/wildcard |
| 6 | `METHOD_NAME` | 方法名通配模式 | pattern, excludes | 遍历所有类 → 遍历方法 → 方法名匹配 |

所有规则共享：
- `enabled: boolean` — 是否启用
- `excludes: string[]` — 排除的类模式（**通配符 `**` 支持**）

### 3.2 规则扫描执行

新增 `RuleBasedScanner`（不是 EntryPointDetector）：
1. 接收 `ClassMetadataRegistry` + `List<ScanRule>`
2. 过滤出 `enabled` 的规则
3. 遍历 `registry.allClasses()`（只走一次，避免重复遍历）
4. 对每个类，逐条规则匹配
5. 匹配成功 → 提取目标方法 → 生成 `EntryPoint`（group = 规则 ID 或固定值 `RULE`，source = AUTO_SCAN）
6. 去重（同类 + 同方法 + 同描述符只保留一个）

### 3.3 内置探测器与自定义规则的关系

```
扫描结果 = 内置探测器结果（启用的） ∪ 规则扫描结果（启用的规则）
```

两者结果 union 后去重，一起通过 diffScanCandidates 与已保存清单比较。

## 4. 数据模型

### 4.1 ScanStrategy（外层）

```java
public class ScanStrategy {
    private int version = 1;
    private String activeProfileId;         // 当前激活方案 ID
    private List<ScanProfile> profiles;     // 方案列表
}
```

### 4.2 ScanProfile（方案）

```java
public class ScanProfile {
    private String id;              // 唯一标识
    private String name;            // 显示名称
    private String description;     // 描述
    private boolean builtin;        // 是否内置（内置不可编辑/删除）
    private Map<String, Boolean> detectors;  // {"REST": true, "DUBBO": false, ...}
    private List<ScanRule> rules;   // 自定义规则
}
```

### 4.3 ScanRule（规则）

```java
public class ScanRule {
    private String id;             // 唯一标识
    private String name;           // 显示名称
    private boolean enabled;       // 是否启用
    private String kind;           // ANNOTATION_METHOD / ANNOTATION_CLASS / PACKAGE / INTERFACE_IMPLEMENT / CLASS_NAME / METHOD_NAME
    private String annotation;     // kind 1-2：注解全限定名
    private String package;        // kind 3：包名
    private boolean recursive;     // kind 3：是否递归子包
    private String interfaceName;  // kind 4：接口/基类全限定名
    private String pattern;        // kind 5-6：通配模式
    private List<String> excludes; // 排除类模式列表
}
```

## 5. 存储层级

### 5.1 全局配置

- **路径**：`D:/.callgraph/scan-strategy.json`
- **内容**：内置方案 + 用户全局自定义方案
- **用途**：无项目级配置时的默认值

### 5.2 项目级配置

- **路径**：`<项目根目录>/.callgraph/scan-strategy.json`
- **内容**：与全局结构一致，**存在即覆盖**
- **覆盖规则**：
  - 加载时，先用全局配置，再用项目级配置覆盖 `activeProfileId` 和 `profiles` 数组
  - 内置方案（builtin=true）始终从全局同步，项目级不改内置方案

## 6. 后端实现

### 6.1 新增文件

| 文件 | 职责 |
|---|---|
| `model/ScanStrategy.java` | 顶层配置模型 |
| `model/ScanProfile.java` | 方案模型 |
| `model/ScanRule.java` | 规则模型 |
| `service/ScanStrategyService.java` | 加载/保存/合并策略（参照 NoiseRuleService 双层模式） |
| `engine/entry/RuleBasedScanner.java` | 通用规则扫描引擎 |
| `web/ScanStrategyController.java` | REST API |

### 6.2 修改文件

| 文件 | 改动 |
|---|---|
| `EntryScanService.java` | 接收策略参数，按策略运行探测器 + 规则扫描 |
| `ProjectsController.java`（可选） | 扫描端点增加策略参数 |

### 6.3 REST API

```
GET    /api/scan-strategy                  → 当前生效策略（全局+项目合并）
PUT    /api/scan-strategy                  → 保存项目级策略
GET    /api/scan-strategy/global           → 读取全局策略
PUT    /api/scan-strategy/global           → 保存全局策略
GET    /api/scan-strategy/profiles         → 可用方案列表（供前端下拉）
POST   /api/projects/{id}/entries/scan     → 增加策略参数（策略ID或完整配置）
```

## 7. 前端实现

### 7.1 扫描策略下拉

在扫描按钮 `#btnEntryScan` 旁新增下拉选择器：

```
[扫描入口] [标准扫描 ▼]
```

- 点击下拉 → 列出所有可用方案（内置 + 自定义）
- 切换方案 → 立即生效（保存到项目级配置）
- 记住上次选择（存入策略 JSON 的 activeProfileId）

### 7.2 管理策略弹窗

下拉末尾有「管理扫描策略…」选项 → 弹出管理面板：

**布局**：
- 左侧：方案列表（~200px 窄边栏）
  - 列表项：方案名称 + 内置标签 + 当前激活标记
  - 底部：+新建、复制、删除（不可删除内置方案）
- 右侧：方案编辑区
  - **基本信息**：名称、描述
  - **探测器开关**：4 个 checkbox（REST / Dubbo / 定时任务 / Main）
  - **自定义规则表格**：每条规则一行（名称、类型、状态、简述），可增删改
    - 新增/编辑 → 按规则类型弹出不同表单：
      - ANNOTATION_METHOD / ANNOTATION_CLASS：文本框[注解全限定名] + 排除列表
      - PACKAGE：文本框[包名] + checkbox[是否递归] + 排除列表
      - INTERFACE_IMPLEMENT：文本框[接口全限定名] + 排除列表
      - CLASS_NAME / METHOD_NAME：文本框[通配模式] + 排除列表
  - **保存按钮** → toast 提示沿用现有组件

## 9. 关键约束

- **默认向后兼容**：未配置任何策略的项目 → "标准扫描"方案 → 行为与现有完全一致
- **规则扫描结果不重复**：内置探测器与自定义规则的结果联合后去重（按 className + methodName + descriptor）
- **管理面板只编辑项目级配置**：全局配置需通过 REST API 直接编辑 JSON 文件
