# 调用链存储由图重构（树 → 图）技术方案

状态：已实现（v1.2）

## 1. 背景与问题

**问题根因**：当前调用链用**树**存储（`CallNode` 内嵌 `children`），同一方法在多条路径被复制为独立子树。

实测（spark-live-classroom，单入口 `RequestController#getRequestListBySid`）：
- 该入口真实调用 **957 个唯一方法**（178 个类），但树节点数 **50000**（撞 `MAX_NODES_PER_ROOT` 上限被截断），冗余约 **52 倍**。
- 单入口缓存 **64MB**；批量 46 入口聚合旧格式高达 **1.4GB**，导致进入项目卡死。
- 冗余来源：① 树沿路径复制方法（主因）；② 环（2287 个 cycle 节点）加剧复制；③ `MethodKey` 序列化 7 个字段，其中 4 个派生 getter（`className/identifier/simpleClassName/display`）重复。

**目标**：改用**图**存储（节点表 + 边表），每个方法只存一次，调用关系存为边。根治 52 倍冗余。

**目标体积**：单入口 64MB → **1-2MB 量级**；批量聚合 1.4GB → 数十 MB 量级。

## 2. 取舍决策（用户已确认）

| 决策点 | 选型 |
|---|---|
| 旧缓存处理 | **直接废弃旧缓存**：`AnalysisResult.schema=2`，读到旧格式（schema≠2）触发重新分析 |
| 环（cycle）语义 | **方法级环标记**：构建期 DFS 判环，命中则将该 callee 方法的 `cycle` 置 true，渲染期直接读，不动态重算 |
| 图节点字段 | **带 display**：节点存 `owner/name/descriptor` + 一个派生 `display`；前端需展示 `className/simpleClassName` 由 owner 解析或前端现拼；丢弃 `identifier` |

## 3. 数据模型

```json
{
  "schema": 2,
  "graph": {
    "methods": [
      { "i": 0, "owner": "com/foo/Bar", "name": "pay",
        "descriptor": "(I)V", "source": "PROJECT", "display": "pay(int)", "cycle": false }
    ],
    "roots": [0, 5, 12],
    "edges": [ { "f": 0, "t": 5, "invoke": "VIRTUAL", "line": 42 } ]
  },
  "stats": { "...": "沿用" },
  "methodFrequency": [ "...沿用现有去重结构..." ]
}
```

### 类定义（新增，包 `engine.model.graph` / `model`）

| 类 | 字段 |
|---|---|
| `GraphMethod` | `int id`、`MethodKey key`(owner/name/descriptor)、`SourceType source`、`String display`、`boolean cycle` |
| `GraphEdge` | `int from`、`int to`、`InvokeType invoke`、`int line` |
| `CallGraph` | `List<GraphMethod> methods`、`List<GraphEdge> edges`、`List<Integer> roots` |

`AnalysisResult`：删除 `List<CallNode> roots`，新增 `CallGraph graph`、`int schema=2`。

`CallNode` 类整体废弃（不再用于存储；如前端/批量有即时树需求，在渲染层由图现算邻接表，不落盘）。

## 4. 接口 / 数据流向

改图前、后，**对外 REST 语义不变**（前端拿到的仍是 JSON，只是字段从 `roots[]` 树变为 `graph`）：

| 接口 | 改动 |
|---|---|
| `POST /api/analyze` | 响应含 `graph`（节点表+边表）而非 `roots[]` 树 |
| `GET /api/projects/{id}/cache/load-file` | 返回 `AnalysisResult`（含 `graph`），校验 `schema==2` |
| `POST /api/report/excel` | Excel 遍历图邻接表导出，语义不变 |

**数据流**：`ClassMetadataRegistry` → `CallGraphBuilder`（产出 `CallGraph`）→ `AnalysisService.fillStats`（遍历边表统计）→ `AnalysisCacheService.save/load`（`schema=2` 持久化）→ 前端/Excel 用邻接表渲染。

## 5. 构建算法（图化）

`CallGraphBuilder` 核心改造——**DFS/预算/深度/同级去重语义全部保留，只把"挂子节点建树"改为"建边"**：

```
build(root):
  methods.add(root); roots.add(root.id)
  expand(id, depth=0, path={root})

expand(callerId, depth, path):
  ci = registry.get(ownerOf(callerId)); if null return
  calls = registry.callsOf(methods[callerId].key); if empty return
  if depth>=maxDepth: markTruncatedFlag(); return
  for raw in calls:
    res = registry.resolve(...)
    case JDK: continue
    case EXTERNAL: addEdge(callerId, ensureMethod(extTarget), raw); // 不展开
    case SINGLE:
      if cycle(raw.target in path): methods[target].cycle=true; continue
      childId = ensureMethod(target, ...)
      if addEdgeDedup(callerId, childId, raw): expand(childId, depth+1, path∪target)
    case MULTI:
      declaredId = ensureMethod(declared), addEdgeDedup(callerId, declaredId, raw)
      for impl in targets:
        implId = ensureMethod(impl, IMPL)
        if addEdgeDedup(declaredId, implId, raw):  // 深度 +2 判截断
          if cycle(impl in path): methods[impl].cycle=true; continue
          expand(implId, depth+2, path∪impl)
```

- **同级去重**：`addEdgeDedup` 维护 `Map<fromId, Set<toId>>`，已存在的边不重复建（对应原 `attach` 的去重）。
- **环**：原 `recurse` 的 `path.contains()` 判环 → 将 callee 方法的 `cycle` 置 true，**不再为该环边展开**。
- **节点预算**：原 `budget[]` 递减逻辑保留在 `ensureMethod`/`addEdgeDedup`，耗尽即停止展开并标记截断。
- **新增方法**：按 `MethodKey`（owner/name/desc）去重，返回 id，不存在则 append 到 `methods` 并赋 id。

## 6. 统计重构（AnalysisService）

`fillStats` 不再 DFS 树，改为**遍历边表 + 节点表**：
- `totalNodes` = 原树节点语义保留下来的等价指标 → 现定义为 **总调用关系数（求和 edges）**，但为**兼容前端统计展示，保留字段名**；其"去重独立方法数"用 `methods.size()` 分类统计。
- `entryCount` = `roots.size()`。
- `truncated`：构建期由于预算/深度耗尽置位（图级别布尔）。
- `projectMethods/dependencyMethods/externalMethods`：遍历 `methods` 按 `source` 分类。
- `methodFrequency`（入度 + 调用方）：遍历 `edges`，`to` 计 `callCount`，`from` 记为 caller（用 `methods[from].key.getIdentifier()` 组装）。**语义与现有 `AnalysisStatsTest` 完全一致**。

## 7. 前端改造（原生 JS，无 npm/vitest → 手动验证 + 后端单测兜底）

新增**适配层**收敛所有改动点，保持渲染/搜索逻辑结构不变：

```js
let G = { methods: [], adj: new Map(), roots: [] };
function methodOf(id){ return G.methods[id]; }
function childrenOf(id){ return (G.adj.get(id)||[]).map(e=>e.to); }
function buildAdjacency(graph){
  G.methods = graph.methods; G.roots = graph.roots; G.adj = new Map();
  for(const e of graph.edges){
    if(!G.adj.has(e.f)) G.adj.set(e.f, []);
    G.adj.get(e.f).push(e);
  }
}
```

| 前端函数（app.js） | 改动 |
|---|---|
| `nodeEl()` (~1382) | `node.children` → `childrenOf(id)`；`node.method.display` → `methodOf(id).display` |
| `matchNode()` (~1486) | 读 `methodOf(id)` 的 `display/owner/className` |
| `collectMatches()` (~1503) | 递归改邻接表 |
| `runGlobalSearch()` (~1640) | `currentResult.roots` → `currentResult.graph.roots` |
| `focusMatches()` (~1527) | `nodeRegistry` 键改为 methodId |
| `renderResult`/`renderSingleEntryResult` (~762) | `result.roots` → `result.graph.roots` |
| 环/截断徽标 (~1415) | `method.cycle`，截断用图级标记 |

## 11. 实施结果与落地偏差（已实现）

**总体**：图核选型按本方案落地，`CallGraphBuilder#buildGraphRoots` 产出 `CallGraph`（`methods` 去重节点表 + `edges` 边表 + `roots` 根索引），`AnalysisResult` 升级 `schema=2`，旧缓存（schema≠2）触发重新分析。

**实现与方案的偏差（均为等价值落地）**：

| 设计点 | 方案表述 | 实际落地 |
|---|---|---|
| 环标记 | 构建期 DFS 判环，callee `cycle=true` | 一致：`markCycle` 在单实现/多实现分支命中路径环时置位 |
| 同级去重 | `Map<fromId,Set<toId>>` | 一致：`seenEdgesPerParent` + `addEdgeDedup` |
| 前端适配层 | 全局 `childrenOf/methodOf` | 改为**惰性 `rootsOf(result)` 适配器**：根 `children` 为 getter 首次访问才由邻接表建子节点，环节点返回空列表；渲染/全局搜索共用同一对象身份命中 `nodeRegistry`。等价但更省内存 |
| 节点预算 | `ensureMethod`/`addEdgeDedup` 递减 | 一致：`MAX_NODES` 触顶即停止展开并标截断 |
| 方法标识展示 | `key.getIdentifier()` 现拼 | 一致：`GraphMethod.display` 存 `getIdentifier()` 完整标识 |

**测试结论（`mvn test` 全量，101 用例）**：图改造新增的 `CallGraphBuilderGraphTest`、`AnalysisControllerTest` 图断言、`ExcelReportGeneratorTest`、`AnalysisStatsTest` 等**图相关用例全部通过**。剩余 4 处失败均为**非图路径的既有环境性问题**，不在本次改造范围：
- `GitPrepareServiceTest`（真实 JGit 克隆 + javac 桩，测试文件未随本改造改动）3 例。
- `AnalysisControllerTest#test_scanEntries_badPath_rejected`：`compileIfNeeded` 对不存在路径 `Files.walk` 抛 `NoSuchFileException`→500（`compileIfNeeded` 非本改造改动）。

**体积收益**：设计中目标单入口 64MB→1-2MB、批量 1.4GB→数十 MB。**图去重机制已生效（每个方法仅存一次、调用存边），但端到端体积实测需以 spark-live-classroom 项目做前后基线对比确认**（见下节）。
