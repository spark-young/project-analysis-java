## 1. 一句话定位

给**内网**用的 **Java 工程静态分析 Web 工具**：喂给它一个已编译的 Java 工程（本地目录 / `.jar` 文件 / Git 仓库自动拉取编译），自动发现**交易入口**（REST 接口 / Dubbo 服务 / ElasticJob 作业 / main 启动类），按入口自顶向下构建**方法调用链**，输出**调用次数分析**、**样板方法过滤治理**与**中文 Excel 报告**。

纯静态分析（ASM 读字节码，不加载不执行被分析代码），**零出站网络**，默认**只绑 `127.0.0.1`**。

## 5. 总体架构与设计思路

### 5.1 数据流（自顶向下）

```
输入源
 ├─ 本地目录 ──────────────────────────┐
 ├─ .jar / .war 文件 ──────────────────┤
 └─ Git 仓库(地址/分支/Token)           │
     └→ GitPrepareService(异步任务)     │
         ├ JGit 克隆（或复用已有工作区） │
         ├ 探测工程类型                 │
         ├ 需要编译 → MavenCompileService(逐行回调 mvn 输出)
         └→ 产出可分析的项目目录 ───────┘
                    ↓
        ClasspathResolver（布局识别 + 构建产物目录向上归一）
                    ↓
        ClassMetadataRegistry（Phase A：SKIP_CODE 索引类头/方法表/注解）
                    ↓
        EntryPointDetector SPI 扫描交易入口
        REST / DUBBO / ELASTIC_JOB / MAIN
                    ↓
        EntryList（清单是分析的真实输入，落盘 entries.json）
                    ↓
        BatchAnalyzeService → CallGraphBuilder（图结构：节点表 + 边表）
                    ↓
        AnalysisResult(JSON) → 前端渲染 + ExcelReportGenerator → xlsx
```

### 5.2 核心设计要点

1. **两阶段字节码解析**：Phase A 用 `ClassReader.SKIP_CODE` 快速索引全部 class（类层次 / 方法表 / 注解）；Phase B 只对需要展开的类做全量 Code 解析提取调用指令。
2. **调用点解析语义**：虚调用按**静态接收类型**解析；接口/抽象方法 → 枚举注册表内全部具体实现（含 default 兜底）；JDK 包排除；类未知 → EXTERNAL 叶子。只做**向下**调用链，不做反向回溯。
3. **调用图用「图」不用「树」存储**：`CallGraph` = 去重节点表 + 边表，前端按需展开成树。根治了同一节点在多个分支里重复序列化导致的 JSON 膨胀。
4. **入口探测器 = SPI**：实现 `EntryPointDetector`（type / label / detect）+ `@Component` 即接入，主流程不改。
5. **双层配置模型**：**全局层** `D:\.callgraph\*.json` + **项目层** `<项目>/.callgraph/*.json`；项目层存在即覆盖全局。过滤规则额外支持**三态覆盖**（继承全局 / 强制启用 / 强制禁用）。
6. **内置（builtin）语义**：内置扫描方案与内置过滤规则**本体以代码为准，不落盘**，只有 `enabled` 采纳外部值，升级 jar 即自动刷新 → 用户永远有可用默认值，不会被旧配置卡住。
7. **过滤是视图层剪枝**：命中规则的节点连同子树从展示与统计中消失，**底层调用图数据不动**，改规则只重渲染（结果区有「⟳ 刷新过滤」）。
8. **调用次数口径 = 不同调用位置的计数**：去重键 = `调用方方法键 @ 行号`，跨入口不重复累加。页面数字 / 行内导出 / Excel 三者口径一致。
9. **缓存跟着项目走**：项目级缓存放 `<项目>/.callgraph/cache/`（jar 型项目放 `<jar路径>.callgraph/cache/`），复制/移动项目即带走缓存；项目变更（Git commit / pom 改动 / 重新编译）自动失效。
10. **异步任务模型**：Git 导入与分支切换都是「提交任务 → 返回 jobId → 前端轮询」，单线程执行器避免并发抢资源；编译输出进 `JobLogBuffer`（环形缓冲，默认 60 行）实时回吐给前端滚动框。
11. **安全设计**：默认只绑 `127.0.0.1:8080`；被分析项目只读不执行；零出站网络（但 Maven / Git 会访问你配置的私服——这是分析他工程的必要动作）。

## 8. 部署与使用说明

### 8.1 环境要求

| 依赖 | 是否必需 | 用途 |
|---|---|---|
| **JDK 11+**（必须是 JDK，不能是 JRE） | 必需 | 运行工具；无构建工具的工程走 javac 路径 |
| **Maven**（`mvn` 在 PATH） | 必需 | 编译被分析工程（Git 导入自动编译、分支切换重新编译）；定位本地仓库拼 classpath |
| **Git**（`git` 在 PATH） | Git 场景必需 | 克隆、分支/Tag 切换 |

### 8.2 构建

```bash
mvn clean package -DskipTests
# → target/project-analysis-java.jar
```

> Windows 下若 jar 正在运行，文件被锁会导致 `repackage` 失败 → 先停服务再打包。

### 8.3 启动

Windows 双击 `start.bat`（自动做 Java / Maven / Git 体检、打印数据目录与访问地址、等端口就绪后开浏览器）；Linux / macOS 用 `bash start.sh`。

手工启动：

```bash
java -jar target/project-analysis-java.jar        # → http://127.0.0.1:8080
```

### 8.4 部署到服务器（供其他机器访问）

工具**默认只监听 `127.0.0.1`**，部署到服务器后只有服务器本机能打开。要供他人访问需覆盖监听地址：

```bash
java -jar project-analysis-java.jar --server.address=0.0.0.0            # 启动参数（推荐）
CG_ADDR=0.0.0.0 java -jar project-analysis-java.jar                     # 环境变量
java -jar project-analysis-java.jar --server.address=0.0.0.0 --server.port=9090
```

用 `start.bat` / `start.sh` 时设 `CG_ADDR=0.0.0.0` 即可。

验证监听地址（应看到 `0.0.0.0` 或 `::`，而不是 `127.0.0.1`）：

```bash
ss -lntp | grep 8080                  # Linux
netstat -ano | findstr :8080          # Windows
curl http://<服务器内网IP>:8080/       # 从其他机器或本机走内网 IP 验证
```

再确认防火墙/安全组已放通端口。

> 绑 `0.0.0.0` 意味着同网段任何机器都能访问，请自行保证网络隔离；不需要远程访问时保持默认 `127.0.0.1`。

### 8.5 使用流程

```
① 导入项目（本地目录 / .jar / Git 仓库）
        ↓
② 维护交易入口清单（自动扫描 + 手动添加 → 排除不需要的）
        ↓
③ 按需配置过滤规则（去样板方法）与扫描策略
        ↓
④ 开始分析 → 查看调用链 / 调用次数分析 → 导出 Excel
```

页面上三步有明确编号与视觉分隔，Step 2 是唯一入口汇合点，Step 3 是唯一分析入口。

### 8.6 配置项

| 配置 | 位置 | 默认 |
|---|---|---|
| 监听地址 | 环境变量 `CG_ADDR` 或 `--server.address` | `127.0.0.1`（仅本机） |
| 端口 | 环境变量 `CG_PORT` 或 `--server.port` | `8080` |
| 数据目录 | `-Dcallgraph.home=` 或 `CALLGRAPH_HOME` | Windows `D:\.callgraph` → 失败回落 `~/.callgraph` → 再回落系统临时目录 |
| 本地 Maven 仓库 | `-Dcallgraph.maven.repo=` 或 `CALLGRAPH_M2_REPO` | 自动定位（settings.xml → Maven 安装目录 → `~/.m2/repository`） |
| Git 工作区根 | `callgraph.git.work-root` | 数据目录下 `workspaces/` |

### 8.7 数据落盘位置（接手必看）

**全局** `<数据目录>/`：`projects.json`（项目注册表）、`noise-rules.json`（全局过滤规则）、`scan-strategy.json`（全局扫描策略）、`workspaces/`（Git 克隆工作区）。

**项目级** `projectDataDir(项目路径)/`：

| 项目形态 | 项目级 `.callgraph` 位置 |
|---|---|
| 目录型（Maven 工程根、target/classes、classes+lib） | `<项目目录>/.callgraph/` |
| **jar / war 型** | `<jar 所在目录>/<jar 文件名>.callgraph/` |

内含 `entries.json`（入口清单）、`noise-rules.json`（项目级过滤规则）、`scan-strategy.json`（项目级扫描策略）、`cache/`（`analysis_result.json` 主缓存 + 入口级缓存）。

> **jar 加文件名后缀**是为了避免"jar 是文件、不能往里建目录"以及"同目录多个 jar 互相覆盖缓存"。逻辑收口在 `CallgraphPaths.projectDataDir()`，共 5 处调用点。

## 9. 约束与教训（勿动 / 必守）

### 9.1 硬性约束

1. **JGit 固定 `5.1.3.201810200350-r`**，依赖内网私服，**不可升级**。
2. 部署服务器**必须装 Maven**；Git 场景建议也装 git CLI。运行需 **JDK 而非 JRE**。
3. **仓库 Token 不持久化**，每次导入手动填写（当前设计如此）。
4. **Git 场景一期只支持 Maven 工程**（含多模块）。Gradle 的 Git 自动编译不在范围内（会明确提示用户手动编译后走本地方式导入）。
5. **默认只绑 `127.0.0.1`**，零出站网络；要对外访问必须显式覆盖并自行保证隔离。
6. **本地导入一律不编译**（这是已确认的产品约定）：不管用户给的是 `target/classes`、`classes+lib` 还是 jar，都要求用户**自己先编译好**。工具的编译只发生在 **Git 场景**（克隆后 / 切换分支后）。
7. **过滤只影响展示与导出**，不改动底层调用图数据。
8. **前端不引入构建工具**；改完静态资源必须提升 `index.html` 的 `?v=` 版本号。
9. **Git 拉取用固定本地目录 + 增量更新**，不要每次重新 clone。

### 9.2 工程规范

- 方法签名统一格式：`全限定类名#方法名(参数类型短名列表)`，构造器为 `#<init>`。前端用 `readableFullSig` / `descriptorParamNames` 等共享函数格式化，后端用 `MethodKey.getIdentifier()`，**不要各写一套**。
- 调用次数口径去重键固定为 `调用方方法键 @ 行号`，改动会同时影响页面数字、行内导出、Excel 三处。
- 新增交易入口类型：实现 `EntryPointDetector` + `@Component`，不要改主流程。
- 项目级数据目录一律走 `CallgraphPaths.projectDataDir()`，**不要自己拼 `Paths.get(projectPath, ".callgraph")`**（jar 型项目会失败）。
- 只读路径不要创建目录：`hasAnyCache` 之类只做 `Files.isDirectory` 判断，避免仅浏览列表就在用户项目里建出空目录。
- 缓存目录必须落在**项目内**，不回落全局缓存。

### 9.3 踩过的坑

| 坑 | 结论 |
|---|---|
| **`<项目>/target` 当项目导入 → 项目名显示成 "target"** | 用户很容易只贴到 `target` 或 `target/classes`。已修：`ClasspathResolver` 对位于 `target`/`build` 内的路径**向上回找含 pom.xml/build.gradle 的祖先**作为工程根；`registerLocal` 也会把注册路径归一化。`classes + lib` 等布局不受影响（防误伤）。 |
| **jar 当项目导入 → `.callgraph` 创建失败** | 往 `xxx.jar\.callgraph` 建目录必然失败。已修：jar 型项目的项目级目录用 `<jar路径>.callgraph`。 |
| **项目卡片误报"磁盘目录已被移除"** | `existsOnDisk` 原来只判 `Files.isDirectory`，jar 路径必为 false。已修：jar 文件也算有效项目，且直接判 `compiled=true`。 |
| **Git 导入"承诺自动编译"但实际没编译** | `GitPrepareService` 的 `mavenCompileService` 曾是**注入未使用的死字段**。已修：检测到 `pom.xml` 就真的执行 `mvn compile`，失败则不注册项目（保留已克隆目录便于重试）。 |
| **同一个 URL 导入失败后 5 分钟不能重试** | 去重索引原来连 `FAILED` 一起拦。已修：`FAILED` 不拦截。 |
| **文案指向不存在的按钮** | 卡片提示曾写"点击重新分析"，但该按钮早已移除；另有"进入项目后将自动编译"的假承诺。已改为按 LOCAL/GIT 分流的准确文案。 |
| **"正在加载"永远一句话不变** | 老页面里有个废弃遮罩也用了 `id="loadingText"`，`$('#loadingText')` 取到的是不可见的那个，所有阶段文案都被丢进黑洞。已修：唯一化 id + 分步进度组件（步骤清单 + 进度条 + 3 秒后出现的耗时秒表）。 |
| **编译期间进度条卡住不动** | mvn 编译长且无输出。已修：`MavenCompileService` 支持逐行回调，`JobLogBuffer` 环形缓冲回吐，前端进度条下方滚动日志框（内容不变不碰 DOM，避免轮询重置滚动位置）。 |
| **IDEA 里跑着 + 外面 `mvn clean compile`** | IDEA 的 run 配置用 `-classpath target/classes`，类在**进程启动时**加载；外部 `mvn clean` 删掉重建 `target/classes` 后，运行中的 JVM 仍在跑**旧字节码**，现象是「改了没生效」。验证时用 `java -jar` 单独起（换个端口），别和 IDE 实例并存。 |
| **测试/状态检测遍历整棵工程树太慢** | `/api/projects` 曾对每个项目做 3 次全树递归且不排除 `.git`/`target`。已修：源码遍历跳过 `.git`/`target`/`build`/`out`/`node_modules` 等，删除冗余遍历，加 20s TTL 状态缓存（打开/注册/删除时失效）。 |
| **`Files.walk` 不要用于状态检测** | 用 `Files.walkFileTree` + `preVisitDirectory` 返回 `SKIP_SUBTREE` 才能真正剪枝。 |
| **换行符治理** | 仓库用 `.gitattributes` 的 `* text=auto` 统一，索引存 LF；`*.bat` 强制 CRLF、`*.sh` 强制 LF。**编辑工具可能插入 LF**，提交前用字节级检查（`CRLF 数 / bareLF 数 / BOM`）自检一次，避免整文件 EOL churn。 |
| **`.bat` 中文必须 GBK 保存** | `cmd.exe` 按代码页解码脚本，UTF-8 保存的中文会被截断执行报错，`chcp 65001` 救不回来。`start.bat` 是 **GBK + CRLF**。 |
| **`pom.xml` 缺 `maven.compiler.source/target`** | JDK ≥ 17 下默认 source 5 会直接报"不再支持源选项 5"，务必显式声明。测试夹具 pom 已处理。 |
| **写文件带 BOM** | 被分析产物或 `pom.xml` 含 BOM 会导致 mvn 读不了（`'modelVersion' is missing @ line 1, column 10`）。保持 UTF-8 无 BOM。 |
